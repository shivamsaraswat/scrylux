# Phase 3 Milestone 4: system extraction

A threat model can now be read by the generation model. **Start extraction** on a new **Draft** tab queues a worker job (`extract_system`) that reads the threat model's ready sources and asks the model for a **draft** system: processes, data stores, external entities, data flows, trust boundaries, assets and assumptions. Every item, and every security flag the model proposes on an element, carries a rationale and a citation: the label of a chunk that was sent in the request and a passage quoted from it, which Scrylux checks is really in that chunk. The draft is stored in its own tables, apart from the threat model, and is shown read-only as a diagram and a list, marked as proposed by AI. Nothing is written to `elements`, `threats` or `mitigations`: accepting items is Milestone 5, proposing threats is Milestone 6.

## Security implications (Development Workflow: prompt construction, a provider adapter change, four routes, a new boundary)

- **Document text now reaches a generation model.** This is the first milestone in which the text of a person's confidential documents is sent to a model that follows instructions. A hosted provider receives it. The Draft tab says so, naming the provider, before the control that starts an extraction and on every visit; it says the text stays in the install when the provider is local (Principle VI).
- **Prompt injection is the new surface.** A document is untrusted input. Defences, each held by a test (`apps/api/test/extract-system/injection.test.ts`, `checks.test.ts`, `content.test.ts`):
  - the document goes only into one section of the request, delimited by a random value drawn for each request, so it cannot close the section by typing an end marker; the instructions are outside it and say the section is data;
  - chunks are named `c1`, `c2`… and items name each other by short references the model chooses; no chunk or database identifier reaches the model, so a citation outside the request cannot even be written;
  - the model is offered no tool;
  - the answer must match a fixed strict schema (the JSON Schema is identical for every request) and a per-request set of checks, and every quote must be a passage of the chunk it cites, whitespace aside;
  - the only effect of an answer is a stored draft that is not part of the threat model; the page renders it as text.
  **Accepted:** a document can still change what is proposed, including a component its design does not have, when it can quote its own text in support. A reviewer sees the quote; Milestone 5 is the human accept step.
- **A fix in the provider layer (`packages/llm/src/attempts.ts`).** The note sent to the model when an answer is invalid used zod's own message, and for an unknown field that message names the field the model wrote. That note travels outside the marked content section, so a document could have planted text there through the model's answer. The note now uses fixed text for every issue and an allow-list of messages. A new test group shows nothing the model wrote reaches the next request (`packages/llm/test/attempts.test.ts`).
- **Four authenticated routes** under `/api/v1`, defined with `defineOperation` so the router and the OpenAPI document agree: `GET` and `POST /threat-models/{id}/extraction`, and `GET` and `DELETE /threat-models/{id}/draft`. The start answers `201` as `POST /jobs` does. `POST /jobs` refuses the new kind. No error answer holds a source's name or any text of a draft.
- **Broadening (FR-068):** any signed-in account can start an extraction on any threat model, and read and discard any draft. There are no roles before Phase 6. The constitution records it as a justified widening; a draft names who started it and when.
- **Nothing of a draft in a log, a job record or an error.** The two write routes log one line (account, threat model, job). A canary test seeds distinctive text through the whole path and finds it nowhere but the draft's tables (`apps/api/test/extract-system/canary.test.ts`). A new test shows the Scrylux file, the OTM file and both reports never hold a draft (`apps/api/test/contract/v1/draft.test.ts`).
- **Spend.** Each request is gated by the job's token and cost caps against its worst case and by an output limit; one extraction of a threat model is queued or running at a time; the account's three-job limit counts extractions. Open until Phase 6: many accounts.
- **The worker gains no credential.** The API still never loads the code that sends a provider request (`apps/api/test/worker/imports.test.ts`, extended).
- Constitution **1.17.0** (a MINOR, see below); `docs/threat-model/` rebuilt in a running Scrylux (63 elements, 399 threats, 361 mitigations): the `Drafts` store, three data flows (`Document text for generation`, `Draft writes`, `Draft queries`), 23 threats the rules derived for them, each decided by the README's table, three threats of the model as a whole (a fabricated or misdirected citation; a draft's text in a log, record, export or report; any account starting an extraction and reading or discarding every draft) and three earlier entries revised. **You approved the Milestone 3 and Milestone 4 additions on 2026-11-09**, and the README records that date. I made the 23 decisions by the table and the evidence named in each mitigation.

## The constitution amendment (Principle II, Principle V)

**1.16.0 → 1.17.0, a MINOR.** Principle II said that once any LLM-backed feature exists, a change to a prompt, adapter or extraction pipeline must pass the eval harness. The harness arrives in Milestone 7, so no such change could pass until then. ## What changes for every install

- **Migration 018** adds six tables (`drafts`, `draft_sources`, `draft_read_chunks`, `draft_items`, `draft_asset_holders`, `draft_citations`), extends the job kind and failure-category checks, and adds a unique index that allows one queued or running extraction per threat model. Deferrable composite foreign keys let items be inserted in any order. A deleted chunk's citation keeps its row with a null chunk and the page says "Source deleted". Forward only; the schema tests are in `packages/db/test/drafts-schema.test.ts`.
- **Two new settings**, both read by the app and the worker: `EXTRACTION_CONTEXT_CHARS` (default 36000, 2,000 to 2,000,000) and `EXTRACTION_MAX_OUTPUT_TOKENS` (default 12000, 1,000 to 32,000). Both are checked at start-up.
- **Prompt files ship in the image**: `apps/api/prompts/extract-system/` (the instructions and eight fixed retrieval questions). The `Dockerfile` copies `apps/api/prompts`. A hash of the files and the schema is stored with each draft.
- Extraction needs a generation provider (`LLM_PROVIDER`) and, for threat models larger than the budget, an embedding provider with up-to-date embeddings. Without them the Draft tab says what is missing and everything else works as before.

## Decisions to review

From clarification and planning (the spec carries them):

- **Assets and assumptions live in the draft only.** The threat model has no record for them; whether accepting one adds a record is Milestone 5's decision.
- **A valid citation** names a chunk that was sent and quotes it. Weak models will retry more; that is the price of a machine-checkable citation.
- **Refuse while any source is waiting or processing**, naming how many; a failed source does not block and the draft names it as left out.
- **Each flag has its own citation.** A flag the documents do not mention stays "not assessed".
- **No approximate vector index.** `plan.md` said this milestone would add one. Planning found that retrieval always filters to one threat model (at most 10,000 chunks at the default limits), where an approximate index is at its weakest and can return too few rows, and the embeddings have no fixed dimension to index. Retrieval compares the query embeddings with every chunk of the threat model, exactly, in one pass. `plan.md` and the roadmap say so.
- **The model sees labels, not identifiers.**
- **A cut-off answer is not retried** until the operator raises the output limit or changes the model, as for "input too large". Starting again after a failure applies the same retry rules.
- **A citation stores a span, not the quote**, so deleting a source leaves none of its text in a citation.
- **What changed a draft's validity is derived, not stored**: "the sources changed" is computed from the draft's own source rows, with no timestamps.

From implementation:

- **Measured: the ranking query.** The first version took 17 to 25 seconds at 10,000 chunks of 3,072 dimensions against a 2-second target. TOAST and compute were both wrong guesses; the cause was Postgres re-parsing the query vectors for every chunk. `WITH q AS MATERIALIZED` brought it to **0.5 to 0.7 s**, documented in `research.md` #6.
- **Measured: `gpt-6-astra` costs $5.96 for a full extraction at the output limit**, above the default `JOB_COST_CAP` of 5, because of its tier ceiling. It is an explicit exception in `caps.test.ts` and the documentation says `JOB_COST_CAP=6` is enough for it.
- **Silent truncation by a local server.** Ollama cuts an input longer than its context without an error, so Scrylux cannot detect it. The documentation makes the context length a requirement of extraction and gives the number for the default budget (32,768 tokens); a local model also needs `LLM_TIMEOUT` raised (the default is 300 s, and a large local extraction can exceed it). `docs/ai-providers.md#extraction` says both.
- **A source that changes while the job waits** makes the run fail with the transient category `sources_changed` and the job is re-queued with backoff, so a source that finishes meanwhile is read instead of being left out.
- **`RunContext.beforeRequest` gained an optional `maxOutputTokens`**, so the cap gate counts the extraction's own output limit and not the provider's default.
- **T065 found nothing to fix** in the earlier layer beyond the retry note.
- **The layout of the draft diagram is computed** (`packages/core/src/draft-layout.ts`): a grid of at most four columns, boundaries sized to hold their members. The draft diagram is read-only and never writes a position.
- **Tests that truncate `jobs` now say `CASCADE`** (six existing files), because migration 018's foreign key from `drafts` to `jobs` makes a bare `TRUNCATE jobs` fail. The new draft contract test joins the serial `jobs` group in `apps/api/vitest.config.ts`.
- **`POST /jobs` says where a kind is started.** It refused `extract_system` (and the ingestion kinds) already, because its body accepts only `provider_check`, but with the schema's generic "Invalid discriminator value". It now answers `kind: This kind of job is started from a threat model's Draft tab.` ("Sources tab" for the ingestion kinds), as `contracts/http-api.md` says, with a test (`jobs.test.ts`, FR-045a, SC-012).
- **Counts that grew:** the `/api/v1` operation counts in `auth.test.ts` and `validation.test.ts` go from 45 to 49, and the OpenAPI test lists the four new operations. `openapi.json` is regenerated.
- **Playwright has a fourth project, `draft`**, after `sources`, because it starts a worker of its own (see Verification).
- **An untracked `.claude/settings.local.json` in the working tree** (`allowLocalBinding` for the agent's sandbox, so it could reach the local test database). It is not part of this change; `.gitignore` (line 20) already ignores it, so it cannot be committed by accident.
